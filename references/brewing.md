# 拟方、比较与修方

本包包含[一一完整经验库及历史总账、发布者的实冲与手冲记录](../knowledge/README.md)。本指南负责把这些材料用于当前杯，不宣称处理法决定某个唯一配方。

先按[一一知识闭环流程](yiyi/workflow.md)阅读适用层级；完整因果关系在经验库，不以本页的候选动作摘要取代它。经验库中的作者偏好、机理解释和“已验证”措辞仍需和总账、实际运行、当前使用者约束对照。

## 先找依据

1. 同一使用者、同豆同批的完整配方和反馈优先。名字相同不代表批次相同。
2. 缺同豆证据时，比较2–3个接近案例。首先看处理法，再结合烘焙、豆龄与保存、品种、产区、器具及目标。公开标签风味与实际品饮分开。
3. “全水洗＋延长发酵”等复合标签需同时保留。不要见“发酵”就套低温或日晒路线；实际干净度、发酵表现和收敛感可以修正初始分类。
4. 无足够案例就说明来源缺口，用示例或一般起点提出待试方案，不编造近邻。别人写的“已解决”要回查是否真的复冲；未执行建议不能当结果。

最低限度的方案依据表：参照杯／条件差异／实际参数和反馈／本次借用与不采用的部分。详细解释写在本杯record.md，面对用户先展示结论与关键取舍。

## 目标与参数

可与用户确认的目标：香气与风味清晰、酸甜平衡、入口到余韵的结构、口感与干净度。不同人的偏好分别保存。浓度、萃取程度和均匀性用于提出解释；无测量时不能从“薄／苦／涩”直接断言TDS或EY。

以下仅为试验方向，需结合当前杯的反馈与过程证据：

| 候选动作 | 可能目的 | 必须考虑的代价／条件 |
| --- | --- | --- |
| 研磨细一点 | 尝试增加表达、强度或酸甜展开 | 可能增加粉床阻力、延长排水或增加苦涩；不能只靠总时间判堵 |
| 提高前中段温度 | 尝试增强展开 | 也可能放大苦味或收敛感；记录各段变化 |
| 降尾段温度或减少尾段过粉水 | 尝试改善尾端杂、涩 | 可能损失余韵、甜感或强度；不是所有苦涩都来自尾段 |
| 增加总水 | 调整比例与过粉用水 | 萃取和稀释同时改变，不能保证更浓或更淡 |
| 固定总水，部分改原生旁通 | 区分过粉萃取与稀释 | 明确过粉水、旁通水、旁通温度；不能承诺消除豆子本身的缺陷 |
| 调停顿、流速、段数 | 尝试改变接触与排水安排 | 参数联动；核对逐段曲线，不用单一流速形态证明机理 |
| 调粉量或RPM | 满足份量、噪声或个人偏好 | 粉床与研磨结果可能变化；没有校准不能宣称颗粒均匀度或浓度必然改变 |

## 无历史时的起点

`examples/standard.recipe.json`为**拟方示例**：15g、240ml、51档、90 RPM、三段93／92／91℃。它用于说明完整格式，不是所有浅烘水洗的推荐答案。已有用户偏好、同豆证据或较深烘焙时需要调整并说明原因；不要把它当作实测经验。

先问已有个人研磨习惯；C40、ZP6与xBloom之间没有在本包验证的通用换算。若使用者提供标定，在其偏好文件中保存设备、区间及“经验近似”身份，不外推成粒径等价。

## 喝完再修

按热／温／凉记录用户实际喝到的香气、风味、酸质、甜感、口感、余韵及负面表现。评分须同时保留量表；未反馈不补0分或满意，另一位品饮者不能继承本人的评价。

列出：想改善什么、保留什么、候选原因的依据与反例、准备改哪些参数、预期及代价。优先单变量；组合变化按组合效果解释。新版本另存，审核之后仍需新杯启动指令。

值得复用的结论附适用范围和对照杯。未经明确复核的经验放raw；经使用者指定的审核人认可具体结论后才标certificated。案例太少或跨批次时保持不确定，反例到来保留旧记录并缩小适用范围，不自动改“权重”或宣布科学因果。
