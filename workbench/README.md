# BrewFlow 制作台

项目作者　**花炉咖啡·尹壹壹** · **SevenMeds**

在同一份 SQLite 中，用豆批关联订单、配方版本、实际冲煮和个人反馈。顾客在豆单上点单，制作人到制作台接单、拟方和确认出杯。

## 第一次打开

在仓库根目录运行以下命令。首次使用会建立空白工作台库存，已有工作台数据库的用户可以跳过初始化，把启动命令的 `--db` 指向自己的文件。独立点单模块 `ordering/` 使用另一套表结构。

```sh
cd workbench
python3 -c 'import schema; schema.init_db()'
python3 -m coffee_product.server --db coffee_inventory.db
```

打开 [库存](http://127.0.0.1:8765/inventory) 录入豆子，在[个人品饮](http://127.0.0.1:8765/tastings)添加品饮人，然后从[豆单](http://127.0.0.1:8765/menu)点单。在[制作台](http://127.0.0.1:8765/studio)选择粉量、审核配方、查看当杯报告。点单支持全量搜索，可以修改或取消尚未制作的订单。

## AI 与配方依据

在 [AI 设置](http://127.0.0.1:8765/studio?view=ai)选择主用模型和备用模型。Codex 使用本机登录，可选择型号、推理强度及 Fast；DeepSeek 支持在本机保存凭据、查看 token 使用量和费用估算，也可以配置 Ollama。

拟方读取当前豆卡、同豆历史、饮用人的反馈，以及随仓库发布的一一拟方流程、六层方法、冲煮经验库与总账。每份建议列出可核对的原文。若本机已取得 v1.9.4 可在 `coffee_product/knowledge/yiyi-v1.9.4/references/` 放入 `AGENT.md` 和 `萃取框架.md` 两份原文，重启后用这两份材料取代公开流程与方法摘要。库存、品鉴和所选资料会随拟方请求发送给当前选用的模型服务。

新杯规则草案默认 15 g、1:15、60 RPM，粉量可选。相同豆批的旧配方可以另存新版本。保存反馈时保留品饮者原话，留空表示尚无评价。确认出杯时显示将扣除的粉量；如有实际差异，先填写实际耗豆。

## 连接机器与查看过程

默认启动命令可用于库存、拟方、点单和手工记录。开启网页真机执行需先按[主仓库安装说明](../README.md#安装)准备蓝牙依赖，再使用此前核对过的本机设备地址。从 `workbench/` 运行以下命令，替换地址占位符。

```sh
../.venv/bin/python -m coffee_product.server --db coffee_inventory.db \
  --enable-bluetooth --device-address '你的设备地址'
```

网页全机模式在当杯确认后启动。机器明确报缺水时会显示补水提示；能确认尚未发送启动指令时可按原方重试。分段注水、杯中液重和根据相邻采样算出的流速使用同一时间轴。采集收到结束信号或满足无更新条件后固定曲线；机器屏显时间和人工核对保留独立记录。

想用外磨粉由机器注水时，使用仓库已有的[免磨命令与配方约定](../references/recipe.md)。工作台里的自磨模式支持记录该杯。
