# 冷启动知识与案例

本目录让首次安装者有实际可查的拟方依据：一一提供六层框架与参数关系，历史配方和反馈提供比较案例，个人档案说明参数取舍属于谁。无需连接原库存系统。

```text
当前豆子、目标、个人约束
          ↓
同批历史 → 无完整同豆配方时，对照2–3个近邻
          ↑                ↑
   按豆记录 log      一一经验 raw + 类型模板
          ↓
证据、候选动作、取舍 → 审核配方 → 明确开始 → 新杯记录
          ↑                                      ↓
   有条件的已审核知识 ← 具体结论审核 ← 对比与反馈
```

首次出方先查案例索引，按处理法优先，再结合品种、产区、烘焙、保存、器具和目标比较。可用`rg -n '74158|水洗|旁通' knowledge/log knowledge/source-snapshot`定位，随后读完整记录，不能只用命中句。完整同豆案例不足时列出实际找过的材料和差异。

反馈修方先读[一一流程](../references/yiyi/workflow.md)与[证据追踪规则](../references/yiyi/knowledge-loop.md)，回到基准杯和当前个人目标，比较候选动作及代价。历史JSON中的`recipe`是设定快照，不是可以整份直接下发的配方文件；将选定参数另存为当前用户的新配方，经过preview及审核再执行。

## 已带入的数据与边界

- 一一原始运行25条，含19条豆子关联记录与6条设备验证；失败、超时、未收到完成信号均保留。并非25杯满意咖啡。
- 发布者本地16次BLE冲煮尝试的结构化提取，保留全部已解码重量样本、状态事件、配方快照、错误和未确认状态。握手失败和重试分开；不把尝试数当杯数。
- SQLite快照26条冲煮记录、8条个人评价，保留原ID、原参数及原文。覆盖C40、ZP6、V60、Origami、Kalita、水质与机冲经验；内容空缺的记录仍为空缺。数据库豆信息是导出时快照，不能倒推历史冲煮时的保存状态。
- 本地Markdown中已有的豆子条件、拟方对照、品饮反馈、修订方案及跨杯比较一起保留。以上来源可能描述同一杯，不能直接相加；只按明确ID关联，不凭同日或同名自动合并。

## 提取口径与更新

[catalog.json](catalog.json)记录来源相对位置、来源文件指纹、公开副本指纹和未随包的引用。原始来源保持在作者本地；此处是公开副本，改写链接并移除设备序列号、地址、主机绝对路径与原始报文。没有随包的库存图片、网页服务实现会明确标注，不能冒充可打开的证据。

本地会话文件格式为`brewflow-session-extract-v1`，不是原始JSONL。`events`保留事件序号、主机时间、接收时间和已解码事件；`weights`按`weight_columns`保存全部重量样本，不平滑、不取峰值、不覆盖取杯后的读数。屏显、物理末滴与人工采纳的188g等值仍以杯次文字记录为准。提取文件不直接输入运行报告程序。

用户可以公开冲煮与评价资料；技能不会自行上传以后产生的记录。随包冷启动数据只读，新用户的偏好、杯次与知识写到自己的工作目录，更新技能不覆盖个人积累。
