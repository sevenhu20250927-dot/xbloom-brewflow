## 原始格式与代码约束（2026-11-05）

用户要求：能够确定性处理的格式、边界和异常交给代码；Agent 负责提出配方及解释口味依据，不能临时决定跳过检查或修改已审核数值。

原始结构来自第三方 skill **v1.3.2**、提交 `ccc0c1d6d7bf10bef7d2685528dd5a796f5cbf2f` 的[配方示例](https://github.com/ryunana/xbloom-studio-recipe-skill/blob/ccc0c1d6d7bf10bef7d2685528dd5a796f5cbf2f/examples/ethiopia-duwancho.recipe.json)。本机安装示例与该提交一致。这是程序的输入格式，随后编译成蓝牙指令；不是已经验证可直接导入官方 App 的文件标准。

```text
根对象：cupType、doseGrams、recipe
根对象可选成对字段：bypassMl、bypassTempC
recipe：grinderSize、rpm、grandWater、pours
pours 每项：volume、temperature、flowRate、pattern、pausing、vibBefore、vibAfter
```

**原有三层字段全部必填，只允许上述字段。** 旁通字段必须同时提供；同时省略表示沿用旧配方的旁通关闭状态，明确关闭则写 `0/0`。不接受别名、注释或额外说明字段，不自动补旁通温度。豆子名称、风味、评分等留在索引、库存及冲煮记录中。

本项目的唯一执行规则在 [`protocol.py`](../../scripts/xbloom_bridge/protocol.py)：`load_recipe` 严格读文件，`build_recipe_frames` 校验结构、参数关系并编码。现有文件可直接作为填写样例，未再添加一份容易与实现分叉的 Schema 或模板文件。

```text
JSON 文件 → 严格解析 → 结构 / 数值 / 编码一致性校验 → 预览
                                              └→ 装载 → 单独的开始授权
Python 字典 ─────────→ 同一编码校验 ──────────────┘
```

## 网页创建与保存（2026-11-05）

在本项目网页导航选择“xBloom 配方”（`/xb-recipes`），可新建、查看、复制调参、检查、另存和导出。库存仍由 Brew Guide 管理；配方表单没有绑定未经核定的豆子 ID。

为满足用户要求的确定性执行，网页仅读写本目录：前端表单 → HTTP原始JSON → 与命令行相同的严格解析及编码检查 → 文件落盘。`protocol.parse_recipe`是共享文档入口；HTTP不能先用普通 `json.loads` 丢掉重复键或精度信息。新页也不依赖旧库存API成功才能打开。

新增的 `xbloom_recipes.py`（来源材料未随包：`xbloom_recipes.py`） 只负责文件库，供HTTP与离线测试使用；没有它，安全命名、原子写入和禁止覆盖会散落在HTTP代码里。文件名即名称/版本，机器JSON保持原格式，不增设名称字段或另存元数据。完整写盘后才原子发布，同名并发保存只有一个成功；写盘结果不确定时保留可回读的完整文件，前端保留草稿，不自动换名称重试。

| 接口 | 用途 |
|---|---|
| `GET /api/xb-recipes` | 列出合法配方；坏文件单列错误，不遮蔽其余配方 |
| `GET /api/xb-recipes/<name>` | 查看指定配方与内容指纹 |
| `POST /api/xb-recipes/validate` | 请求体为纯配方JSON；只检查，不保存 |
| `POST /api/xb-recipes/<name>` | 请求体为纯配方JSON；通过检查后新增，重名409，不覆盖 |
